## Project

`refer <job_url>` — CLI that, after the user applies to a job, finds Cornell alumni at that company in relevant roles on LinkedIn, looks up their work emails, drafts a referral-request email from a user-managed template (Claude Sonnet 5.5 fills the blurb), and sends it via Gmail after the user approves each one.

### Decisions (agreed with user)
- **Scraping:** `joeyism/linkedin_scraper` (v3, Playwright/async), installed from GitHub, for the browser/session and job scraping. We add our own `PeopleSearchScraper` (repo has no people search). Its `PersonScraper` is broken against the current LinkedIn DOM, so `referral/profiles.py` replaces it: details-page text → Claude structured output (`models.extract` = `claude-haiku-5-5`, chosen by the user). We also override its `detect_rate_limit`, which gave false positives.
- **Job parsing:** ATS public APIs first (SmartRecruiters, Greenhouse, Lever, Ashby, **Workday**). The user's links usually come via Simplify and are mostly Workday; LinkedIn job URLs via `JobScraper`; anything else → fetch + Sonnet extraction.
- **Candidate selection:** filter to Cornell + current employee + relevant role; the user hand-picks who to contact. No demographic inference.
- **Email lookup:** Hunter.io first, Apollo fallback; only for hand-picked candidates.
- **Composition:** `claude-sonnet-5-5` adapts a fixed user-owned `template.md`; job link, ask, and sign-off stay verbatim.
- **Outreach routes (decided 2026-10-21, revised 2026-10-22):** email only. The LinkedIn connection-note route was removed at the user's request (can't message without Premium); people without an email are listed so an address can be added by hand. Never automate LinkedIn messaging. **Email:** Hunter lookup, **hard-capped at 50 credits/month** (`hunter.monthly_credit_limit`, checked against Hunter's account endpoint before every paid call). Gmail sending (review-then-send, resume attached, never auto-send) is still planned as optional.
- **Safety:** daily/run scrape caps, random delays, `--dry-run`.
- **Note:** for postings where the employer is LinkedIn itself, prefer manual outreach.
- **Anthropic auth:** the key isn't scoped to a workspace, so every request must send the `anthropic-workspace-id` header (`ANTHROPIC_WORKSPACE_ID` in `.env`). In the SDK, pass `default_headers={"anthropic-workspace-id": ...}`.

### Secrets
Stored in `.env` (gitignored, chmod 600). See `.env.example` for keys. Never commit `.env`, `session.json`, `credentials.json`, `token.json`, resumes, or the DB.
